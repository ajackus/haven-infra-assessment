## Genuine tooling error caught and corrected

An initial GitHub Contents API attempt used the create-file operation for
`app/access_control.py`, which already existed as a stub. GitHub rejected it
with HTTP 422 and the message:

```text
"sha" wasn't supplied.
```

The error showed that this was an update, not a create. The existing file was
fetched to obtain its blob SHA, and the update-file operation was then used.
The same fetch-SHA-update sequence was followed for the other existing stubs
and answer documents. No source file was overwritten without first retrieving
its current SHA.
