# B0 — The `count` trap

What does `terraform plan` show when a middle landlord account is removed from the list? Why is
that dangerous here? What's the fix?

## What the plan shows

Command (run against the seeded state, no AWS account needed):

    terraform -chdir=terraform plan -refresh=false -var='landlord_accounts=["la-001", "la-003", "la-004"]'

Removing `la-002` from the 4-account list gives `Plan: 4 to add, 0 to change, 3 to destroy`:

- `landlord_media[1]` **must be replaced**: `haven-media-la-002` -> `haven-media-la-003` (forces replacement)
- `landlord_media[2]` **must be replaced**: `haven-media-la-003` -> `haven-media-la-004` (forces replacement)
- `landlord_media[3]` **will be destroyed**: `haven-media-la-004` (index 3 is out of range for `count`)
- The other two adds are `listing_media` and its lifecycle configuration, which are not in the
  seeded state and are unrelated to this bug.

## Why it is dangerous here

`count` addresses buckets by list position. Removing a middle entry shifts every later account
down one index, so Terraform sees the bucket *names* at index 1 and 2 change. A bucket name
cannot change in place, so it destroys and recreates them. The result is that removing one
landlord (la-002) plans to destroy the existing buckets of la-002, la-003 and la-004. The
la-003 and la-004 buckets are destroyed even though those landlords are staying, and new empty
buckets with those names are created in their place. These buckets hold landlord media, so
applying this would delete other landlords' data, and the plan shows it only as routine
"replace" lines.

## Fix

Use `for_each` keyed by account id instead of `count`, so each bucket is tied to its account
rather than its position:

    resource "aws_s3_bucket" "landlord_media" {
      for_each = toset(var.landlord_accounts)
      bucket   = "haven-media-${each.key}"
      tags     = { landlord_account_id = each.key }
    }

Removing la-002 then plans to destroy only `landlord_media["la-002"]`.

**Not done:** I have not changed `terraform/main.tf`, and I have not run a plan with `for_each`.
Existing state uses index addresses (`[0]`..`[3]`), so adopting `for_each` needs
`moved` blocks or `terraform state mv` first, otherwise it would plan to recreate all four buckets.
