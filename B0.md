# B0 – The Terraform Count Trap

## Problem

Terraform uses the `count` meta-argument to create S3 buckets for landlord accounts. Each resource is identified by its numerical index in the list.

For example:

| Terraform address | Landlord account |
|---|---|
| aws_s3_bucket.landlord[0] | Landlord A |
| aws_s3_bucket.landlord[1] | Landlord B |
| aws_s3_bucket.landlord[2] | Landlord C |

If Landlord B is removed from the middle of the list, the list becomes:

| Terraform address | Landlord account |
|---|---|
| aws_s3_bucket.landlord[0] | Landlord A |
| aws_s3_bucket.landlord[1] | Landlord C |

## What Terraform Plan Shows

Terraform identifies resources by their count index, not by the landlord account's identity.

As a result:

- Index 0 remains unchanged.
- Index 1 now represents Landlord C instead of Landlord B. If bucket configuration depends on the landlord ID, Terraform may plan to replace the bucket at index 1.
- Index 2 is no longer required, so Terraform plans to destroy that resource.

The exact plan depends on how the bucket name and other attributes are configured.

## Why This Is Dangerous

Each S3 bucket may contain landlord-specific property documents, tenant information, screening reports and photos.

An incorrect replacement or destruction can cause:

- Accidental deletion of landlord data.
- Unnecessary infrastructure replacement.
- Service disruption.
- Potential data loss and recovery costs.

This is particularly risky in a multi-tenant application where resources must remain associated with the correct landlord account.

## Recommended Solution

Replace `count` with `for_each` and use stable, unique landlord account IDs as resource keys.

Example:

```hcl
variable "landlord_accounts" {
  type = set(string)
}

resource "aws_s3_bucket" "landlord" {
  for_each = var.landlord_accounts

  bucket = "haven-landlord-${each.key}"
}
```

Example input:

```hcl
landlord_accounts = [
  "L001",
  "L002",
  "L003"
]
```

Terraform will identify resources using stable addresses such as:

```text
aws_s3_bucket.landlord["L001"]
aws_s3_bucket.landlord["L002"]
aws_s3_bucket.landlord["L003"]
```

If L002 is removed, Terraform destroys only the resource associated with L002. The resources belonging to L001 and L003 retain their identities.

## Conclusion

Using `for_each` with stable landlord account IDs is safer than using `count` with positional indexes for independently managed landlord resources. It prevents index shifting from causing unintended changes to unrelated landlord infrastructure.
